# Wave program readiness

Research checked on 2026-10-21. This document records public requirements; it is not an application
or a claim of acceptance.

## Drips Stellar Wave

| Question                   | Verified position                                                                                                                                                                               | Project status                                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Program                    | Drips describes Stellar Wave as a recurring, usually one-week contribution sprint.                                                                                                              | Relevant: this is a public Stellar RPC project.                                                                                     |
| Repository onboarding      | A maintainer signs in, installs the Drips Wave GitHub App on the hosting organization, synchronizes a public repository, applies it to the relevant program, and waits for organizer approval.  | Not performed. The repository is under a personal GitHub account, and app installation/application are external maintainer actions. |
| Selection                  | The Public Goods Association and program organizer retain discretion to accept, reject, suspend, or remove repositories.                                                                        | No eligibility or acceptance claim can be made.                                                                                     |
| Issues                     | An approved repository's maintainer selects issues and assigns Trivial, Medium, or High complexity. Applying the program label in GitHub defaults an issue to Trivial until changed in the app. | The repository has a structured backlog, but no issue has been added to a Wave.                                                     |
| Maintainer operation       | Maintainers are expected to review applications quickly, assign contributors, track work, review PRs, and resolve qualifying work before the Wave deadline.                                     | Contribution and review guidance exists; sustained external response history is not established.                                    |
| Identity and compliance    | Participants must meet age, sanctions, jurisdiction, account, and possible KYC/KYB or phone-verification conditions.                                                                            | Requires the maintainer's own confirmation; not assessed here.                                                                      |
| AI and artificial activity | Low-quality, untested, or not-understood LLM work, Sybil identities, coordinated low-quality work, and point manipulation are prohibited.                                                       | Project policy rejects fabricated contributors and activity; every contribution still requires human review and understanding.      |
| Cost and rewards           | Participation has no platform fee, though claiming may involve network fees. Points have no intrinsic monetary value and reward decisions remain discretionary.                                 | No reward or payment promise is made.                                                                                               |

The official documentation does not publish a universal minimum issue count, star count, contributor
count, or acceptance threshold. Repository quality and genuine maintainership are therefore more
important than reaching an arbitrary backlog total.

## Readiness conclusion

The repository is technically and administratively suitable for future consideration, but it is not
ready to claim program eligibility. The largest evidence gap is genuine external contribution and a
demonstrated maintainer review history. The next milestone is to guide several independent
contributors through scoped issues and high-quality reviewed pull requests before applying.
